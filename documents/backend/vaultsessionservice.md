# VaultSessionService

## Назначение

`VaultSessionService` хранит состояние текущей сессии хранилища: авторизован ли пользователь, нужно ли блокировать приложение при выходе, сворачивании или по таймеру бездействия.

## Роль в системе

Сервис состояния сессии. Используется UI и жизненным циклом приложения для блокировки хранилища и уведомления подписчиков об изменениях.

## Пространство имён / модуль

`SecurePassword`

Источник: `SecurePassword/SecurePassword/VaultSessionService.cs`

## Зависимости

* `Microsoft.Maui.Storage.Preferences` - сохранение пользовательских настроек блокировки.
* `DateTimeOffset` и `TimeSpan` - расчёт времени бездействия.

## Основные свойства и поля

* `StateChanged`
  * Тип: `event Action?`
  * Назначение: уведомление об изменении состояния сессии.
* `IsAuthenticated`
  * Тип: `bool`
  * Доступ: `public get`, `private set`
  * Назначение: показывает, открыт ли доступ к хранилищу.
* `LockOnExit`
  * Тип: `bool`
  * Назначение: настройка блокировки при закрытии приложения.
* `LockOnMinimize`
  * Тип: `bool`
  * Назначение: настройка блокировки при сворачивании приложения.
* `LockOnTimer`
  * Тип: `bool`
  * Назначение: настройка блокировки по таймеру бездействия.
* `InactivityTimeout`
  * Тип: `TimeSpan`
  * Назначение: допустимое время бездействия, сейчас 2 минуты.

## Основные методы

* `MarkAuthenticated()`
  * Помечает сессию как авторизованную, обновляет активность и уведомляет подписчиков.
* `Lock()`
  * Блокирует сессию, если пользователь был авторизован.
* `RecordActivity()`
  * Обновляет время последней активности.
* `ShouldLockForInactivity()`
  * Возвращает: `bool`
  * Проверяет, нужно ли блокировать хранилище по таймеру.

## Логика работы

1. При успешном входе вызывается `MarkAuthenticated`.
2. При действиях пользователя вызывается `RecordActivity`.
3. Таймер или жизненный цикл приложения проверяет `ShouldLockForInactivity`.
4. При изменении настроек или состояния вызывается `StateChanged`.

## Правила использования

* `Lock()` должен вызываться вместе с очисткой загруженного ключа в `keyManager`.
* Настройки блокировки читаются и сохраняются через `Preferences`, поэтому переживают перезапуск приложения.
* Подписчики `StateChanged` должны учитывать, что событие может прийти после изменения любой настройки блокировки.
