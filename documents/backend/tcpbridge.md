# TcpBridge

## Назначение

`TcpBridge` управляет передачей профиля между устройствами: собирает локальные файлы хранилища в ZIP-архив, отправляет его по TCP, принимает архив от другого устройства и безопасно заменяет локальную базу.

## Роль в системе

Высокоуровневый сервис P2P-синхронизации. Сетевой слой делегируется `NetworkService`, а подготовка ключевого файла для переноса делегируется `keyManager`.

## Пространство имён / модуль

`SecurePassword`

Источник: `SecurePassword/SecurePassword/sql(rus)/NetworkProtocols/TcpBridge.cs`

## Зависимости

* `NetworkService` - отправка и приём байтов по TCP.
* `keyManager` - экспорт переносимого `keys.dat`.
* `System.IO.Compression.ZipArchive` - упаковка и распаковка базы.
* `FileSystem.AppDataDirectory` - каталог рабочих файлов хранилища.
* `FileSystem.CacheDirectory` - временные папки для импорта и резервной копии.

## Основные поля

* `VaultFiles`
  * Значение: `keys.dat`, `passwords.dat`, `cards.dat`, `notes.dat`
  * Назначение: полный набор файлов профиля.
* `DataFiles`
  * Значение: `passwords.dat`, `cards.dat`, `notes.dat`
  * Назначение: файлы пользовательских данных, по которым проверяется, что база не пустая.
* `_networkService`
  * Тип: `NetworkService`
  * Назначение: TCP-передача.
* `_keyManager`
  * Тип: `keyManager`
  * Назначение: подготовка ключевого файла для архива.

## Основные методы

* `GetPreferredMode()`
  * Возвращает: `SyncTransferMode`
  * Если локальная база существует, предлагает `Upload`, иначе `Download`.
* `LocalVaultExists()`
  * Возвращает: `bool`
  * Проверяет наличие хотя бы одного файла профиля.
* `HasTransferableVault()`
  * Возвращает: `bool`
  * Проверяет наличие `keys.dat` и хотя бы одного непустого файла данных.
* `GetLocalPeerAddresses()`
  * Возвращает: `IReadOnlyList<string>`
  * Возвращает локальный IP-адрес, если его удалось определить.
* `GetPeerAddressHint()`
  * Возвращает: `string`
  * Формирует текст с IP-адресом текущего устройства или сообщением об ошибке.
* `SendVaultToPeerAsync(string host, CancellationToken token = default)`
  * Возвращает: `Task<SyncOperationResult>`
  * Создаёт ZIP-архив профиля и отправляет его получателю.
* `ReceiveVaultFromPeerAsync(CancellationToken token = default)`
  * Возвращает: `Task<SyncOperationResult>`
  * Принимает ZIP-архив, проверяет его и заменяет локальные файлы.

## Логика отправки

1. Проверяется адрес получателя.
2. Проверяется, что локальная база пригодна для передачи.
3. Создаётся ZIP-архив.
4. Для `keys.dat` вызывается `keyManager.ExportKeyFileForTransfer`, чтобы не отправлять ключевой файл с неподходящими платформенными Argon2id-параметрами.
5. Остальные файлы копируются в архив как есть.
6. Архив отправляется через `NetworkService.SendFlow`.

## Логика приёма

1. Приёмник ждёт архив через `NetworkService.ReceiveFlow`.
2. Архив проверяется: в нём должен быть непустой `keys.dat` и хотя бы один непустой файл данных.
3. Файлы распаковываются во временную папку.
4. Текущие локальные файлы переносятся в резервную папку.
5. Импортированные файлы перемещаются в `AppDataDirectory`.
6. Если импорт падает, локальная база восстанавливается из резервной копии.
7. После успешного импорта `keyManager.ClearLoadedKey` сбрасывает текущий ключ, и пользователь должен войти снова.

## Правила использования

* Перед отправкой профиль должен быть открыт, потому что экспорт ключевого файла требует загруженный DEK.
* Приём профиля заменяет локальные файлы хранилища.
* Не добавлять в архив файлы вне списка `VaultFiles`.
* Ошибки возвращаются через `SyncOperationResult`, чтобы UI мог показать понятный статус.
